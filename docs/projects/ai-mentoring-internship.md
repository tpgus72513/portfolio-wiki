# AI 기반 소상공인 상권 분석·마케팅 지원 플랫폼

> 데이터 분석 결과를 보여주는 데서 멈추지 않고, 소상공인이 수정해 사용할 수 있는 마케팅 초안과 안전 검토 기능까지 연결했습니다.

## 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 형태 | 기업 멘토링 기반 팀 프로젝트 |
| 기간 | 2026.07.06 ~ 2026.07.31 |
| 역할 | 팀장, 기획, AI 마케팅 콘텐츠 기능 개발, 제안 문서 총괄 |
| 주요 기술 | React, Vite, TypeScript, Node.js, Express, PostgreSQL, Prisma, OpenAI API |
| 데이터 | 서울 공공 상권·유동인구·추정매출 데이터 |

## 요약

- **문제:** 소상공인이 상권 데이터를 직접 해석하고, 그 결과를 실제 홍보 문구로 바꾸는 데에는 시간과 비용이 듭니다.
- **접근:** 상권 분석 결과와 매장 정보를 입력받아 여러 종류의 마케팅 초안을 생성하고, 허위·과장 위험 표현을 별도로 검사했습니다.
- **결과:** AI 호출, 규칙 기반 fallback, 안전 검사, 수정 후 재검사를 하나의 웹 흐름으로 구현했으며 현재 백엔드 테스트 48개가 모두 통과합니다.
- **핵심 배움:** 자연스러운 문장을 생성하는 것만으로는 제품이 되지 않으며, 사실성·실패 대응·사용자 수정 과정을 함께 설계해야 합니다.

## 배경과 목적

소상공인은 매출, 유동인구, 주요 연령대, 피크 시간 같은 데이터를 확보해도 이를 어디에 어떻게 활용해야 하는지 판단하기 어렵습니다. 마케팅 문구를 만들 때도 가게의 실제 정보보다 과장된 표현이나 획일적인 AI 문장이 섞일 수 있습니다.

프로젝트는 공공데이터 기반 상권 추천 결과를 **실행 가능한 마케팅 행동**으로 이어주는 것을 목표로 했습니다. 사용자가 매장명, 업종, 대표 상품, 타깃 고객, 이벤트, 선택 상권과 원하는 말투를 입력하면 수정 가능한 홍보 초안을 제공하도록 설계했습니다.

## 내가 맡은 역할과 기여

### 1. 팀장과 기획

- 기업 과제의 요구사항을 초기 아이디어 노트, 입찰 제안서, MVP, 최종 발표의 네 단계로 나누어 관리했습니다.
- 기존 상권 분석 기능 위에 마케팅 콘텐츠 생성 기능을 추가하는 MVP 범위를 정했습니다.
- AI 마케팅 콘텐츠와 제안 문서를 총괄하고, 다른 담당 기능과 연결되는 입력·출력 항목을 조정했습니다.

### 2. AI 마케팅 기능의 end-to-end 구현

Git 기록의 기능 커밋을 기준으로 입력 schema, controller, service, API route, 프론트엔드 화면, 자동화 테스트까지 한 기능의 전체 경로를 구현했습니다.

- 매장 소개, SNS 게시글, 이벤트·쿠폰, 관광객 대상 문구와 생성 이유를 구조화된 JSON으로 반환했습니다.
- 친근함, 활기참, 신뢰감, 간결함, 정중함의 5개 말투가 단순한 어미 변경이 아니라 문장 구조와 리듬에서 구분되도록 규칙을 만들었습니다.
- AI 결과가 매장명, 상품, 타깃 고객 같은 핵심 입력을 실제로 포함하는지 검사하고, 누락되면 사용자에게 불완전한 결과를 전달하지 않았습니다.
- 사용자가 문구를 직접 수정한 뒤 다시 검사하고 복사할 수 있는 화면 흐름을 구현했습니다.

## 가장 어려웠던 점: “AI가 쓴 티” 줄이기

처음 생성한 문장은 문법적으로는 맞아도 상투적인 표현이 반복되고, 가게마다 다른 맥락이 충분히 드러나지 않는 문제가 있었습니다. 단순히 프롬프트에 “자연스럽게 써줘”라고 추가하는 방식으로는 결과를 안정적으로 통제하기 어려웠습니다.

이를 다음과 같이 나누어 해결했습니다.

1. **사실과 스타일 분리:** 매장명, 메뉴, 고객, 이벤트는 사실 입력으로 고정하고, 말투는 별도의 선택값으로 처리했습니다.
2. **말투별 구조 설계:** 5가지 말투마다 문장 길이, 정보 배열, 이모지 사용, 종결 표현을 다르게 설계했습니다.
3. **수정 가능한 초안:** AI 결과를 최종 게시물이 아니라 사용자가 편집하는 초안으로 정의했습니다.
4. **생성 이유 제공:** 어떤 입력과 말투를 반영했는지 함께 반환해 사용자가 결과를 검토할 근거를 만들었습니다.
5. **규칙 기반 대체 문구:** AI 연결이 실패해도 같은 입력으로 기본 문구를 생성해 전체 사용자 흐름이 중단되지 않도록 했습니다.

## 사실성과 안전성 설계

자연스러움만큼 중요한 문제는 AI가 입력에 없는 사실이나 과장된 성과를 만드는 것이었습니다.

- 프롬프트에서 입력값에 포함된 지시문을 실행하지 않고, 제공되지 않은 가격·순위·효능·매출·고객 반응을 만들지 않도록 제한했습니다.
- `최저가 보장`, `매출 보장`, `100%`, `무조건`, `최고`, `1위` 등 근거가 필요한 표현을 규칙으로 관리했습니다.
- 위험 표현을 발견하면 안전한 표현으로 바꾸고, 변경 이유와 수정 방향을 함께 반환했습니다.
- AI 응답이 정상이어도 서버에서 다시 검사했으며, 사용자가 수정한 문구에는 별도의 재검사 API를 적용했습니다.
- API 키가 없거나 호출이 실패하거나 핵심 입력이 누락된 경우 규칙 기반 결과로 전환했습니다.

## 결과 및 검증

- 마케팅 생성 기능을 백엔드와 프론트엔드에 연결해 직접 실행하고, 입력부터 결과 수정·재검사까지의 흐름을 확인했습니다.
- 입력 검증, 5가지 말투, AI 실패 fallback, 입력 근거 확인, 필수 필드 누락, 위험 표현 탐지·자동 수정, API 오류 응답을 자동화 테스트로 다뤘습니다.
- 2026-08-24 기준 프로젝트 백엔드에서 `npm test`를 실행한 결과 **48개 테스트가 모두 통과**했습니다.
- Git 기록에는 AI 마케팅 생성과 안전 검사를 추가한 기능 커밋이 본인 계정으로 남아 있습니다.

## 한계와 다음 단계

- 생성 결과는 게시 가능한 사실을 보증하지 않으며, 사용자가 가격·이벤트 조건·근거를 최종 확인해야 합니다.
- 규칙 기반 안전 검사는 등록된 표현과 변형을 중심으로 동작하므로 모든 과장 표현의 의미를 판단하지는 못합니다.
- 관광 연계 기능은 실제 관광 API가 아닌 샘플 데이터를 사용한 MVP입니다.
- 상권 분석 데이터는 서울 공공데이터를 기반으로 하므로 다른 지역에 바로 일반화할 수 없습니다.

다음 단계에서는 실제 소상공인에게 초안을 보여주고 `수정에 걸린 시간`, `그대로 사용한 문장 비율`, `부자연스럽다고 표시한 표현`을 수집해 자연스러움을 정성 평가가 아니라 반복 가능한 지표로 검증하고 싶습니다.

## 이 프로젝트로 보여준 역량

- 기업 과제 요구사항을 MVP 기능과 일정으로 전환한 기획 경험
- 생성형 AI 기능을 입력 검증부터 UI와 테스트까지 end-to-end로 구현한 경험
- AI 실패, 환각, 허위·과장 표현을 제품 흐름에서 다룬 설계
- 구현 결과를 Git 기록과 자동화 테스트로 검증한 경험
